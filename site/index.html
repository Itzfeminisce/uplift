Uplift

Type-safe file uploads for TypeScript.

Install Quickstart Client React Storage API Rich OSS
Open source TypeScript uploads

Define upload routes once. Use them everywhere.

Uplift turns file uploads into a typed contract between your server and frontend. Build route constraints, auth, storage keys, metadata, and completion hooks in one place, then call route-named upload methods from the client.

Get started GitHub npm

Why Uplift?

Server-driven types Client methods are inferred from the upload contract.
Small fluent API Compose file type, limits, auth, keys, metadata, validation, and done hooks.
Adapter-friendly Use Next.js, Hono, Express, S3, R2, Bunny, Cloudinary, or local storage.

Quickstart

Define routes

import { image, pdf, uplift } from "uplift";
import { s3 } from "uplift/storage/s3";

export const uploads = uplift({
  storage: s3({
    bucket: process.env.S3_BUCKET!,
    region: "us-east-1",
    accessKeyId: process.env.S3_ACCESS_KEY_ID!,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!
  }),
  routes: {
    avatar: image()
      .max("2mb")
      .auth(async ({ req }) => ({ id: req.headers.get("x-user-id")! }))
      .key(({ user }) => `avatars/${user.id}.png`)
      .done(async ({ file }) => {
        console.log(file.url);
      }),

    resume: pdf().max("5mb"),
    gallery: image().max("8mb").multiple(10)
  }
});

export type Uploads = typeof uploads;

Mount a handler

import { createNextHandler } from "uplift/next";
import { uploads } from "@/uploads";

export const { GET, POST } = createNextHandler(uploads);

The client posts to one endpoint with ?route=<routeName>, so one framework endpoint can host every upload route.

Typed Client

import { createUploadClient } from "uplift/client";
import type { Uploads } from "./uploads";

export const upload = createUploadClient<Uploads>("/api/upload");

const avatar = await upload.avatar(file);
const gallery = await upload.gallery(fileList);

Single routes accept File and return UploadedFile. Multiple routes accept File[] | FileList and return UploadedFile[].

React

import { useUploads } from "uplift/react";
import type { Uploads } from "./uploads";

export function AvatarUploader() {
  const upload = useUploads<Uploads>("/api/upload");
  return (
    <input
      type="file"
      accept="image/*"
      onChange={(event) => {
        const file = event.currentTarget.files?.[0];
        if (file) void upload.avatar(file);
      }}
    />
  );
}
upload.avatar.progress;
upload.avatar.isUploading;
upload.avatar.error;
upload.avatar.data;

Storage

import { bunny } from "uplift/storage/bunny";
import { cloudinary } from "uplift/storage/cloudinary";
import { local } from "uplift/storage/local";
import { r2 } from "uplift/storage/r2";
import { s3 } from "uplift/storage/s3";

S3 and R2 use @aws-sdk/client-s3. Bunny and Cloudinary use provider upload APIs. Local storage writes to disk for development and self-hosted deployments.

Builder API

.max("2mb")
.min("10kb")
.multiple(10)
.auth(async ({ req }) => user)
.overrideAuth()
.key(({ user, file }) => `uploads/${file.name}`)
.meta(({ user, file }) => ({ owner: user.id, name: file.name }))
.validate(({ file }) => true)
.done(async ({ file, user, meta }) => {})

JSON validation accepts any schema with a .parse() method. Uplift does not force Zod, Axios, an ORM, or a database client into your app.

Rich Inspection

import { audio, pdf, video } from "uplift/rich";

pdf().pages({ max: 10 }).encrypted(false);
video().duration({ max: "2m" });
audio().duration({ max: "5m" });

Rich inspection is opt-in and currently fails closed until an inspector is wired for the deployment. Video duration checks are designed around ffprobe.
