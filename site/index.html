Open source TypeScript uploads

Define upload routes once. Use them everywhere.

Uplift turns file uploads into a typed contract between your server and frontend. Build route constraints, auth, storage keys, metadata, and completion hooks in one place, then call route-named upload methods from the client.

Get started GitHub npm
uploads.ts 
export const uploads = uplift({
  storage: s3({ bucket, region }),
  routes: {
    avatar: image()
      .max("2mb")
      .auth(requireUser)
      .key(({ user }) => `avatars/${user.id}.png`)
      .done(async ({ file, user }) => {
        await db.user.update({
          where: { id: user.id },
          data: { avatarUrl: file.url }
        });
      }),

    gallery: image().multiple(10)
  }
});
Typed contract

Server-driven client methods

Route names, single vs multiple inputs, and output shapes are inferred from your upload contract.

One endpoint

Simple framework wiring

The client posts to one handler with a route query, so Next.js, Hono, and Express stay boring.

Adapters

Storage without leakage

Use S3, R2, Bunny, Cloudinary, or local storage through the same route API.

Quickstart

Define routes

Single-file routes are the default. Calling .multiple() changes both server and client types.

import { image, pdf, uplift } from "uplift";
import { s3 } from "uplift/storage/s3";

export const uploads = uplift({
  storage: s3({
    bucket: process.env.S3_BUCKET!,
    region: "us-east-1"
  }),
  routes: {
    avatar: image()
      .max("2mb")
      .auth(async ({ req }) => ({ id: req.headers.get("x-user-id")! }))
      .key(({ user }) => `avatars/${user.id}.png`)
      .done(async ({ file }) => console.log(file.url)),

    resume: pdf().max("5mb"),
    gallery: image().max("8mb").multiple(10)
  }
});

export type Uploads = typeof uploads;

Mount a handler

The client posts to one endpoint with ?route=<routeName>. 

import { createNextHandler } from "uplift/next";
import { uploads } from "@/uploads";

export const { GET, POST } = createNextHandler(uploads);
Client

Route-named uploads

Single routes accept File; multiple routes accept File[] | FileList.

import { createUploadClient } from "uplift/client";
import type { Uploads } from "./uploads";

export const upload = createUploadClient<Uploads>("/api/upload");

const avatar = await upload.avatar(file);
const gallery = await upload.gallery(fileList);
React

State over the vanilla client

Each route exposes progress, upload state, error, and last successful data.

import { useUploads } from "uplift/react";
import type { Uploads } from "./uploads";

const upload = useUploads<Uploads>("/api/upload");

upload.avatar.progress;
upload.avatar.isUploading;
upload.avatar.error;
upload.avatar.data;

API

The builder surface

No hard dependency on Zod, Axios, an ORM, or a database client.

.max("2mb")
.min("10kb")
.multiple(10)
.auth(async ({ req }) => user)
.overrideAuth()
.key(({ user, file }) => `uploads/${file.name}`)
.meta(({ user, file }) => ({ owner: user.id }))
.validate(({ file }) => true)
.done(async ({ file, user, meta }) => {})
Rich

Opt-in inspection

Inspection-heavy methods stay behind uplift/rich.

import { audio, pdf, video } from "uplift/rich";

pdf().pages({ max: 10 }).encrypted(false);
video().duration({ max: "2m" });
audio().duration({ max: "5m" });
