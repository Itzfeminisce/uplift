upload.config.ts 
// server
const uploads = uplift({
  storage: s3({ bucket, region }),
  routes: {
    avatar: image()
      .max("2mb")
      .auth(requireUser)
      .key(({ user }) => `avatars/${user.id}.png`),

    gallery: image().multiple(10),
    resume: pdf().max("5mb"),
  }
});

// client — fully inferred
const upload = createUploadClient<typeof uploads>("/api/upload");
await upload.avatar(file); // ✓ typed

Inferred client

Route names, multiplicity, and return shapes are inferred directly from your server contract — zero manual types.

Provider adapters

S3, R2, Bunny, Cloudinary, local, memory, and UploadThing-compatible storage — swap without touching route logic.

No lock-in

No hard Zod, Axios, ORM, or database dependency in the core. Bring only what your project already uses.

Quickstart

Define routes once.

Single-file routes are the default. .multiple() changes both server and client types automatically.

src/server/upload.ts 
import { image, pdf, uplift } from "uplift";
import { s3 } from "uplift/storage/s3";

export const uploads = uplift({
  storage: s3({ bucket, region }),
  routes: {
    avatar: image().max("2mb").auth(requireUser),
    resume: pdf().max("5mb"),
    gallery: image().max("8mb").multiple(10),
  }
});

Positioning

Why Uplift?

UploadThing is great infrastructure. Uppy and FilePond are excellent client upload experiences. Uplift is for teams who want the upload contract itself to be typed, framework-light, and storage-swappable.

↑ Uplift Route contracts + inferred clients. Storage-swappable. No lock-in to a provider or framework.
UploadThing Managed upload infrastructure with UI helpers. Great if you want the full hosted stack.
Uppy / FilePond Rich browser upload widgets. Best for polished drag-and-drop UI experiences.
Direct SDKs Lowest-level escape hatch. Full control, but you wire everything yourself.
